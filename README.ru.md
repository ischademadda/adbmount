# adbmount

[![ci](https://github.com/ischademadda/adbmount/actions/workflows/ci.yml/badge.svg)](https://github.com/ischademadda/adbmount/actions/workflows/ci.yml)
[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

[English version](README.md)

Монтирует память Android-телефона (внутреннюю и SD-карту) в macOS как обычный том с чтением и
записью через **adb**. Не требует расширений ядра (использует [FUSE-T](https://www.fuse-t.org/)) и
ничего не ставит на телефон, нужна только отладка по USB.

```
телефон ──USB── adb ──► adbfs (Go, cgofuse) ──► FUSE-T (NFS) ──► Finder, Python, ffmpeg, foobar2000…
```

В репозитории две части: `adbfs`, демон файловой системы (Go), и `adbmount`, небольшой
shell-скрипт: он находит SD-карту, запускает по одному `adbfs` на том и аккуратно отмонтирует.

## Требования

* macOS (Apple Silicon или Intel)
* [FUSE-T](https://www.fuse-t.org/) и Android platform tools
* Go (только для сборки, версия из `go.mod`)
* Android-телефон с включённой **отладкой по USB**, компьютер должен быть авторизован

## Установка

```bash
brew install --cask fuse-t        # попросит пароль администратора
brew install android-platform-tools go

git clone https://github.com/ischademadda/adbmount.git
cd adbmount
make build                        # соберёт ./adbfs
sudo make install                 # по желанию: копирует adbfs и adbmount в /usr/local/bin
```

`adbmount` ищет `adbfs` рядом с собой (можно задать `ADBFS_BIN=/path/to/adbfs`), поэтому держите
файлы вместе. Чтобы ставить без sudo: `make install PREFIX=$HOME/.local`.

## Использование

```bash
adbmount up            # внутренняя память → ~/mnt/android, SD-карта → ~/mnt/sdcard (находится сама)
adbmount up --ro       # то же, но только чтение (безопасно для просмотра и сканирования)
adbmount up --only sdcard
adbmount status
adbmount down
```

pid-файлы лежат в `~/Library/Caches/adbfs/run`, рядом же логи (`adbmount log sdcard`). Каталог
монтирования меняется через `ADBMOUNT_DIR=/some/dir`. Если подключено несколько устройств, выберите
нужное: `ANDROID_SERIAL=<serial> adbmount up` (серийники покажет `adb devices`).

Прямой запуск:

```bash
adbfs -root /storage/ABCD-1234 -mount ~/mnt/sdcard -volname SDCard [-ro] [-allow-junk]
```

| флаг | значение |
|---|---|
| `-root` | каталог на телефоне, который становится корнем тома (по умолчанию `/sdcard`) |
| `-mount` | локальная точка монтирования, создаётся при отсутствии |
| `-serial` | серийник устройства, если подключено несколько |
| `-adb` | путь к adb (по умолчанию `adb` из `PATH`) |
| `-ro` | только чтение, любое изменение возвращает `EROFS` |
| `-allow-junk` | сохранять macOS-файлы `._*` / `.DS_Store` вместо того, чтобы отбрасывать |
| `-volname` | имя тома в Finder |

`ADBFS_TRACE=1` включает лог каждой операции с временем выполнения.

> **Важно:** режим чтения-записи меняет память телефона напрямую. Если нужно только посмотреть,
> начните с `--ro`, а незаменимое сначала скопируйте. ПО предоставляется «как есть», см. [LICENSE](LICENSE).

## Как это работает

* **Листинг**: один `adb exec-out find … -exec stat` на каталог, кэш на 10 с. Изменения, сделанные
  *вне* маунта (например, самим телефоном), появятся в течение этого окна.
* **Чтение**: файл в фоне стримится в локальную временную копию и уходит вперёд от прочитанного не
  больше чем на 8 МБ. Чтение далеко за пределами уже скачанного (теговые читалки прыгают в конец
  файла) обслуживается отдельным range-запросом через `dd skip=`. Нужны были оба механизма:
  `tail -c +N` сканирует файл с начала и на FLAC в 300 МБ занимал ~1 с.
* **Запись**: файл, открытый на запись, сначала скачивается целиком, правится локально и
  загружается **при flush/close** через `temp file + mv`, так что на телефоне никогда нет
  недописанного файла. Неудавшаяся загрузка оставляет файл «грязным», следующий flush повторит её.
  До закрытия файла писателем на телефоне ничего не появляется (кроме пустого файла после `create`,
  чтобы последующие lookup его видели).
* **Rename/delete/mkdir** — одиночные `mv`/`rm`/`mkdir` на телефоне, поэтому перенос папок внутри
  тома мгновенный независимо от размера.
* **Юникод**: macOS отдаёт имена в NFD, Android хранит NFC (или наоборот). Поиск откатывается на
  обход с NFC-нормализацией, поэтому работают оба написания.
* **macOS-мусор**: `._*`, `.DS_Store`, `.Trashes`, `.fseventsd` и т. д. принимаются, пока файл
  открыт, и затем отбрасываются, поэтому карта не засоряется AppleDouble-файлами. Том также отдаёт
  `.metadata_never_index`, чтобы Spotlight не индексировал телефон.
* **Устойчивость**: временные ошибки adb (device offline, перезапуск демона, «closed») повторяются
  с нарастающей паузой около 10 с. Временные каталоги процесса лежат в
  `~/Library/Caches/adbfs/<pid>-*`; оставшиеся после падения удаляются при следующем запуске.

Замеры на телефоне по USB: последовательное чтение ≈ 17–20 МБ/с, запись ≈ 8–9 МБ/с, сканирование
каталога из ~50 FLAC ≈ 16 с (≈ 0,3 с на файл, упирается в один round trip adb на файл).

## Ограничения

* Запись целиком по файлам: правка одного тега в FLAC на 300 МБ загрузит все 300 МБ заново.
* Нет симлинков, хардлинков, xattr и прав доступа (в `/sdcard` Android их нет).
* Свободное место в Finder обновляется раз в 30 с.
* Осмысленен только один писатель на файл, блокировок нет.
* Только macOS (FUSE-T). На Linux есть варианты лучше, например `adb` + `sshfs`/`madbfs`.
* Для массовой переписи файлов (перекодирование всей библиотеки) гораздо быстрее запускать
  инструмент на самом телефоне (Termux), чем гонять данные через кабель.

## Разработка

```bash
make check      # go vet + go test + сборка
```

`device` (в `adb.go`) — единственное, что файловая система знает о телефоне. В `fs_test.go` он
реализован в памяти, поэтому вся ФС (постраничное чтение, create/write/flush, truncate, rename,
unlink открытых файлов, фильтр мусора, NFC/NFD, back-pressure read-ahead, повтор загрузки)
тестируется без телефона и FUSE. Тесты проверялись мутациями: если сломать flush, unlink или
back-pressure, падают соответствующие тесты.

| файл | роль |
|---|---|
| `main.go` | флаги, чистка временных каталогов, монтирование |
| `fs.go` | FUSE-файловая система (кэш, скачивание, запись) |
| `adb.go` | интерфейс `device` и его реализация через adb, повторы |
| `fs_test.go`, `main_test.go` | устройство в памяти и тесты |
| `adbmount` | скрипт монтирования/отмонтирования/статуса |

## Если что-то не работает

* **Пустой маунт или `Resource busy` при отмонтировании**: `adbmount down` (принудительно
  отмонтирует и убьёт только запущенные им процессы). Никогда не используйте `pkill -f adbfs`: он
  заденет и второй маунт.
* **`no phone visible`**: проверьте кабель, включите отладку по USB и подтвердите запрос
  авторизации на телефоне; `adb devices` должен показывать `device`, а не `unauthorized`.
* **Finder тормозит на огромных папках**: используйте `--ro` для просмотра; каждый каталог — это
  один вызов adb.
* **Созданная на телефоне папка не видна**: подождите до 10 с (кэш листинга).
* **`cannot stat /storage/... on device`**: карта не смонтирована/не разблокирована на телефоне
  или изменился UUID; реальное имя покажет `adb shell ls /storage`.
* **Сборка падает с `fuse.h not found`**: установите FUSE-T (`brew install --cask fuse-t`).
